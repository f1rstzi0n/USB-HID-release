# 参数树与目录维护

`catalog/SW110048.catalog.yaml` 是本仓库 USB 参数树、运行契约、初始化值和目录描述的唯一人工维护来源。CSV、树、分组清单、C 数据和语言资源均由 `tools/catalog/Generate-Catalog.ps1` 派生。原始 DAT/UI 和现场快照已一次性迁移，后续维护从 YAML 开始。

## 修改哪个字段

YAML 按实际树层级组织。`tree` 中的分组具有稳定 ASCII `key`、双语 `title` 和按显示顺序排列的 `children`。每个参数只定义一次；移动整个参数节点即可修改归属和顺序。新增分组时填写 key 和 `zh-CN`、`en-US` 标题，节点编号由脚本生成。

| 字段 | 用途 |
|---|---|
| `device` | 目标、设备名称和类型、固件身份及目录发布版本 |
| `provenance`、参数 `source` | 原始来源、原名称、历史修正和迁移说明 |
| 参数 `name`、`address`、`type` | 线级 ASCII 名称、24 位地址和类型 |
| `elementCount`、`elementSize` | 元素数量和尺寸；复合类型明确填写尺寸 |
| `runtime.access/min/max/visible` | 固件编译的硬权限、范围及显隐规则 |
| `runtime.initial` | MCU 复位时的 RAM 初值 |
| `description.default` | 目录中的默认描述，安装目录不会把它写入 RAM |
| `description.access/min/max/visible` | USB 目录限制；缺省继承硬规则，显式指定只能收紧 |
| `description.unit/enums` | 单位和结构化枚举 |
| `description.widget/remark` | 保留的控件提示与备注，不增加线级协议行为 |
| `uiBindings` | 已支持的主窗口角色、参数名称引用和顺序 |
| `errors` | 错误码对应的目录文案 |

地址使用 `0x` 加六位十六进制，例如 `"0x010103"`。数值按文件中同类参数的格式填写，保留显式引号；复合类型初值使用完整十六进制字节串。脚本拒绝重复字段、名称、地址和 key，未知字段、类型和角色，无效引用，越界或不能表示的数值以及设备容量超限，并报告 YAML 位置。修正错误后重新检查，数量和哈希由生成器计算。

## 初值和目录描述

修改 `description.default` 只改变目录描述。修改 `runtime.initial` 需要重新编译并部署固件，才会改变下次 MCU 复位后的值。迁移保留历史初始化字节；部分初值落在硬写入范围之外，生成器保留这些已注明原因的兼容值，不进行饱和或静默转换。

目录限制受固件硬规则约束，例如硬范围为 0–100 时，目录可设置为 10–90。撤销目录限制也只能回到固件硬规则。地址、类型、元素尺寸或硬规则变更需要配套固件；签名证明包的来源与完整性，不证明旧固件支持新契约。

主窗口绑定生成设备和 Andromeda 的编译期允许表，两端继续校验。修改允许表需要配套编译。新增业务角色需要业务代码支持，YAML 不能定义可执行动作。双语分组标题由 Andromeda 的编译期资源呈现，修改后需构建上位机。

## 维护流程

1. 编辑 YAML。修改分组时移动整个节点，保留原有参数的身份、运行规则和维护说明。
2. 执行 `Generate-Catalog.ps1 -Mode Check`。它在临时目录重建并与正式派生文件核对，维护源和正式产物均保持原样；源有变化而派生文件尚未更新时，检查会指出过期文件。
3. 执行 `-Mode Generate` 更新派生数据。提供 `-HostRoot` 时同时更新 Andromeda 的 USB 分组及相关自动资源；生成器遇到无关模块需要变动时停止并报告。
4. 发布时执行 `-Mode Publish -HostRoot <Andromeda仓库> -KeyName <已有发布钥>`。所有检查、编码、资源生成和签名在暂存目录完成，全部成功后才发布，报告最后写入。
5. 按报告执行所需的固件或上位机构建；通过 Andromeda“工具 → 更新”安装签名 `.acat`。

完整命令、派生文件和工具依赖分别见 [目录入口说明](../../catalog/README.md) 与 [构建发布工具](../../tools/catalog/README.md)。迁移保真证据保存于任务记录，历史数量和初始化摘要用于首次迁移验收，不是日常维护字段。
