# BVPV-USB 协议规范

- **版本**：v4.3（外部参数目录与两遍签名更新）
- **日期**：2026-10-10
- **状态**：线级主版本为4；外部目录以HELLO能力位启用，不支持该能力的既有v4设备沿用完整目录加载。
- **依据**：CLAUDE.md「HID 协议架构（四层，已批准的骨架）」。本文与 CLAUDE.md 冲突时，以本文为准并回改 CLAUDE.md。

## 1. 范围与术语

BVPV-USB 是自研阀门控制器 USB HID 接口的应用层协议。它与 RS485 链路的 BVPV 协议**共享同一参数模型与值编码**，差异仅在传输层（见附录 A 的对应关系）。

| 术语 | 定义 |
|---|---|
| 报表（Report） | 单个 HID 中断传输，固定 64 字节 |
| 分片（Fragment） | 应用报表去掉首个保留字节后的 63 字节 = 2B 分片头 + 61B 载荷 |
| 逻辑消息（Message） | 一个完整的 L2 帧，由 1~68 个分片重组而成，最大 4096 字节 |
| 帧（Frame） | L2 协议数据单元：帧头 + 载荷 + CRC16 |
| 事务（Transaction） | 一次请求帧 + 一次应答帧的配对 |
| 参数地址 | BVPV 三字节地址 `[类][实例][属性]`；树/属性记录使用 3B，单值等请求另跟索引或保留字节 |
| 目录（Catalog） | 设备参数全集（树、属性、主窗口绑定和错误文本），新设备存于外部Flash签名ACAT包 |
| 主机 / 设备 | 主机 = 上位机（PC）；设备 = 下位机（STM32F446 控制器） |

**全局约定**：除参数地址和 §7.13 的 ECDSA r/s、公钥坐标明确采用大端外，多字节字段均为**小端**（LE）。保留字节/位填 0；帧 FLAGS、树记录种类和结构严格校验，未知扩展属性 TLV tag 可按长度跳过（§10）。

## 2. L0 HID 报表层

USB 复合设备 Interface 0 = HID，厂商自定义 Usage Page `0xFF00`、Usage `0x0001`，中断 IN/OUT 端点各一，报表描述符定义输入/输出报表各 64 字节，轮询间隔 1ms。

```
应用报表（64B）= [0]=保留（恒 0x00） [1..2]=分片头 [3..63]=载荷（61B）
```

Windows HID API 输入/输出缓冲为 **65B**：`[API ReportID=0][上述64B应用报表]`。设备描述符没有编号 Report ID；API 首字节与应用报表首个保留字节不能合并或漏发。USB 端点仍传输 64B。

## 3. L1 分片层

### 3.1 分片头

```
byte0 = [SOF:1][EOF:1][SEQ:6]
byte1 = MSGID
```

| 字段 | 取值 | 语义 |
|---|---|---|
| SOF | bit7 | 逻辑消息首片 |
| EOF | bit6 | 逻辑消息末片 |
| SEQ | bit5..0 | 片序号，每条消息内从 0 递增、**模 64 回绕** |
| MSGID | 0..255 | 消息标识，每发完一条逻辑消息递增（模 256） |

- **单报表消息**（≤61B，参数读写的常见路径）：SOF=1、EOF=1、SEQ=0，零分片开销。
- **MSGID 双向独立**：主机发送方向与设备发送方向各自维护自己的 MSGID 计数器，互不干扰。
- 4096B 最大消息 = 68 片，SEQ 在第 64 片后回绕到 0；连续性校验一律按模 64 运算，回绕属正常。

### 3.2 发送规则

1. 一条逻辑消息的所有分片使用同一 MSGID，SEQ 从 0 连续递增（模 64）。
2. 首片置 SOF，末片置 EOF，中间片两者皆 0。
3. 消息全部发完后，发送方 MSGID 加 1（模 256）。

### 3.3 接收规则（四层防错）

| # | 机制 | 防住的场景 |
|---|---|---|
| 1 | SEQ 连续性校验：每片须等于（前片 SEQ + 1）mod 64，跳号即丢弃整个重组缓冲 | 固件缓冲溢出丢中间片——杜绝"片1+片3"错误拼接 |
| 2 | 重组中途收到新 SOF：丢弃半成品，以新 SOF 重新开始 | 主机进程崩溃重启、上条消息尾巴与下条消息串话 |
| 3 | MSGID 逐片比对：与首片不同即丢弃重组缓冲（SOF 片除外，按规则 2 处理） | 设备/主机复位后跨消息拼接 |
| 4 | 重组超时：首片到达后 **200ms** 内未收齐，丢弃重组缓冲 | 对端死在消息中间，接收方不永久等待 |

### 3.4 无片级 ARQ（设计依据）

片丢失 → 整条消息作废 → 由 L2 事务层"应答超时 + 读可重试一次"恢复。USB 中断传输有 CRC16 + 握手 + DATA0/1 翻转位，不静默丢包；剩余风险仅为固件丢报表、设备复位、主机重启三类，检测 + 再同步已足够。重组完成后由 L2 帧的 LEN 与 CRC16 兜底。

## 4. L2 帧格式

```
[0]     SVC     服务码（§5）
[1]     FLAGS   bit7=方向（0=请求，1=应答）；bit2..0=协议版本=4；bit6..3 保留填 0
[2..3]  TID     事务 ID，LE；主机自增，应答回显
[4..5]  LEN     载荷字节数 N，LE，0..4088
[6..]   载荷（N 字节）
[6+N]   CRC16   低字节
[7+N]   CRC16   高字节
```

- 帧总长 = 8 + N，最大 4096B = L1 最大逻辑消息，自洽。
- **CRC16-CCITT-FALSE**：多项式 `0x1021`、初值 `0xFFFF`、不反射、异或出 `0x0000`，覆盖 SVC 至载荷末字节。选 CRC16 而非 BVPV 的 sum8：USB 虽不静默丢包，CRC 兜底重组错误与固件 bug，成本仅 2 字节。
- **应答帧约定**：FLAGS.bit7=1、SVC 回显、TID 回显、**载荷首字节 = 状态/错误码**（§9，0=成功），其后为服务定义的应答数据。错误应答可只含状态码 1 字节。

### 4.1 事务规则

1. **停等单事务**：任意时刻最多一个未完成事务；主机发出请求后必须等应答或超时，才能发起下一事务。
2. TID 由主机自增（初值任意，模 65536），应答回显；主机校验回显，不符则丢弃该应答并视为超时。
3. **超时**：读类事务 200ms，参数写入 500ms；MSC BEGIN/BLOCK/ABORT、MCU BEGIN/BLOCK/ENTER_BOOTLOADER/RUN_APP 为 2000ms，MSC/MCU FINISH 为 15000ms（含全盘回读与提交）。整个请求发送及响应共用一个截止时间，分片重组仍为 200ms。
4. **重试**：读类事务超时或 CRC 错误可原样重试一次；**写类事务绝不自动重发**（沿 BVPV 规则，防重复生效）。
5. 设备收到 LEN 越界、CRC 错误的帧：不回应答（主机走超时路径），可计诊断计数器。
6. 设备收到 CRC 正确但 FLAGS 非 0x04 的请求，返回 FLAGS=0x84、原 SVC/TID、仅 status=0x0A，不执行业务。主机遇旧版应答明确终止连接，不重试协商或降级。

## 6. 参数模型与值编码

### 6.1 参数地址

参数地址为 `[类][实例][属性]` 三字节（如 `CM` = `0x69 0x01 0x03`），不按小端整数倒序。TREE_PULL、ATTR_SNAPSHOT_PULL 与变化记录直接使用 3B；VALUE_READ/WRITE 跟元素索引，ATTR_EXT_READ/ATTR_CORE_READ/STATE_READ 跟保留 0 字节。DAT 来源的 `0xFFFFFFFF` Undefined 哨兵在线级规范化为 `0xFFFFFF`，仍占一个目录项。

### 6.2 数据类型表

| 编号 | 类型 | 字节数 | 编码 |
|---|---|---|---|
| 0x01 | UINT8 | 1 | — |
| 0x02 | UINT16 | 2 | LE |
| 0x03 | UINT32 | 4 | LE |
| 0x04 | UINT64 | 8 | LE |
| 0x05 | INT32 | 4 | LE（补码） |
| 0x06 | FLOAT32 | 4 | IEEE 754 binary32，LE |
| 0x07 | FIXED16.16 | 4 | 有符号 Q16.16，LE |
| 0x08 | UFIXED16.16 | 4 | 无符号 Q16.16，LE |
| 0x09 | UFRAC16 | 2 | `0x4000`=0%，`0xC000`=100%，LE |
| 0x0A | TEXT8 | 8 | 定长 ASCII 字段，NUL 结尾、余位填 0 |
| 0x0B | TEXT16 | 16 | 同上 |
| 0x0C | TEXT32 | 32 | 同上 |
| 0x0D | COMPOSITE | 按目录定义 | 多字段组合，逐字段 LE |
| 0x00 | UNDEFINED | — | 仅地址 `0xFFFFFF`、权限 OOO 的目录占位；禁止值读写 |

类型集与 BVPV `BvpvValueCodec` 对齐；编号为本协议自定义。DAT 目录中的别名 token 在线级归并：`INT32LE` 按 INT32（0x05）处理，`FRAC16.16` 按 FIXED16.16（0x07）处理（线格式相同，目录生成时归一）。⚠️ FLOAT32 是**小端字节**——与竞品的 hex 大端文本方向相反，排查 captures 时最常见的混淆点。

### 6.3 权限编码

| 值 | 含义 | 读 | 写 | EEPROM 持久 |
|---|---|---|---|---|
| 0x01 | RWA | ✓ | ✓ | ✓（写入进 pending 集） |
| 0x02 | ROO | ✓ | — | — |
| 0x03 | RWO | ✓ | ✓ | — |
| 0x04 | OWO | — | ✓（需主机显式确认） | — |
| 0x00 | OOO | — | — | — |

与 DAT 目录的五种权限一一对应。协议保留 RWA pending 语义；本 fake 分支不实现 EEPROM 保存，不得把成功写入、RAM 读回或 OWO 成功应答视为持久化完成。

## 7. 各服务载荷定义

### 7.1 HELLO（0x01）

请求载荷：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | host_proto_ver | 固定单字节 `0x04`，请求总长必须为 1 |

应答载荷：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | status | 状态码 |
| 1 | dev_proto_ver | 设备协议版本 `0x04` |
| 2 | device_type | 板级类型（拨码 PD11/PB13/PB12）：1=LOW，2=MED，3=HIGH，0=未知 |
| 3..4 | max_msg | 最大逻辑消息字节数（=4096） |
| 5 | frag_payload | 分片载荷字节数（=61） |
| 6..7 | reasm_timeout_ms | 重组超时（=200） |
| 8 | name_len | 设备名长度 |
| 9.. | name | 设备名 ASCII（如 `BV500-USB`），不含 NUL |
| 9+N..10+N | capabilities | u16 LE；bit0=`0x0001` 动态属性，bit1=`0x0002` 参数持久化，bit2=`0x0004` MCU 更新，bit3=`0x0008` 外部参数目录；当前Fake APP为 `0x000D` |
| 11+N..14+N | metadata_revision | u32 LE；当前元数据修订号，0 保留 |

HELLO 载荷版本不为 0x04 时，应答仅含 status=`0x0A`；自身协议版本由应答 FLAGS=0x84 表明，不附额外 dev_proto_ver 载荷。请求不是恰好 1 字节时回 `0x08`。主机应停止连接和后续服务。

N 等于 name_len，成功应答总长严格为 **15+N**（包含 status）；name 为非空可打印 ASCII。capabilities 尾部和非零 metadata_revision 在 v4 中必需，禁止按旧格式截断。**不增加参数树格式标志、不用 capability 位协商树格式**：所有 v4 连接都使用 §7.3。HELLO 不传 USB UID、业务序列号、光盘版本或 CRC；VID/PID/完整 MCU UID 来自 USB 描述符，光盘字段由 MSC_INFO 读取。

### 7.2 游标分块（TREE_PULL / ERRTEXT_PULL 共用模式）

优于竞品 `START`/续传的有状态模式：**无状态、乱序安全、天然防串话**。

请求载荷：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0..1 | start_index | 起始条目索引（首请求填 0；续传填上一应答的 next_index） |
| 2..3 | max_bytes | 本应答最大数据字节数（不含 status/next_index 头） |

应答载荷：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | status | 状态码 |
| 1..2 | next_index | 下一条目索引；**0xFFFF = 全部完毕** |
| 3.. | entries | 条目序列，总字节 ≤ max_bytes；**条目不可跨界拆分** |

请求总长严格为 4B。主机从 start_index=0 开始，直到 next_index=0xFFFF；非终页 next_index 必须等于起始游标加本页完整记录数，且严格前进。start_index 大于总记录数回 `0x05`；等于总数时返回空终页。空间不足以容纳下一条完整记录时回 `0x08`，不返回不前进游标。

### 7.3 TREE_PULL（0x02）—— 参数树

请求：`[start_record:u16LE][max_bytes:u16LE]`。成功应答在通用 status 之后为 `[next_record:u16LE][records...]`；max_bytes 仅限制 records 区，不含 status 和 next_record。

| 记录 | 字节格式 |
|---|---|
| 分组 | `[kind=0x01][node_id:u16LE][parent_id:u16LE][key_len:u8][ASCII key]` |
| 参数 | `[kind=0x02][parent_id:u16LE][address:3B]` |

根节点 ID=0 隐含存在，不单独传输；其余 ID 非零且唯一。父节点必须先出现，key 为 1..255B 可打印 ASCII。记录按生成树的前序排列；参数的父节点指向所属分组，也可为隐含根。记录不跨页，游标按全部记录计数（分组和参数均计 1），0xFFFF 为完成标志。

每个参数恰好出现一次，与 ATTR_SNAPSHOT_PULL 地址全集一致；属性分页不要求和树参数出现顺序一致，主机按地址合并。拒绝未知 kind、重复节点、未知父节点、循环、重复/未知/遗漏参数地址、截断和不前进游标；全部树与属性验证成功前不发布部分目录。

本分支生成 2183 个参数、135 个分组、2318 条树记录。分组层级与排列来源于仓库快照中 UI CSV 的 TreeIndexName，按 CMD 关联 DAT；未覆盖参数归入 `extension.0xNN` 并按地址排序。固件只编译 ASCII key，Andromeda 编译对应中英翻译；未知 key 原样显示。运行时 USB 不读取电脑端 DAT、UI CSV 或 MSC 目录。

C/C# 共用树向量（包含 status）：`00 FF FF 01 01 00 00 00 01 67 02 01 00 01 01 07`，表示分组 id=1、parent=0、key=`g`，以及 parent=1、address=`0x010107` 的参数，整页结束。

### 7.4 保留服务码（0x03）

v4 移除 ATTR_PULL；请求此服务码返回服务不支持。名称、核心属性和扩展属性由 §7.5a 同一修订快照提供。

### 7.5 ATTR_EXT_READ（0x04）—— 扩展属性（按需单查）

请求载荷：`[0..2]=参数地址 [3]=保留`。

应答载荷：`[0]=status`，随后 TLV 序列（解析至 LEN 耗尽，未知 tag 跳过）：

| tag | 内容 | 值编码 |
|---|---|---|
| 0x01 | Min | 按参数类型（§6.2） |
| 0x02 | Max | 同上 |
| 0x03 | Default | 同上 |
| 0x04 | EnumValues | 重复条目：`[4B 无符号枚举值 LE][1B UTF-8字节数][UTF-8文本]` |
| 0x05 | Unit | UTF-8 单位串（如 `mTorr`、`%`） |

TLV 头 = `[1B tag][2B len LE]`，len 按字节计数。主机严格校验 UTF-8、禁止内嵌 NUL，拒绝截断、重复已知属性和重复枚举数值；未知 tag 按长度跳过。枚举文本单项不超过 255B。数值型枚举项的 u32 是选项的整数值，实际参数值仍按参数类型编码（如 FLOAT32 枚举值 1 在线级值字段为 `00 00 80 3F`）。TEXT 默认值仍遵循 ASCII 值编码，不使用 UTF-8。

### 7.5a ATTR_SNAPSHOT_PULL（0x12）—— 合并属性快照

连接与全量重同步使用此只读服务。请求载荷恰好 8 字节：
`[start_index:u16 LE][max_bytes:u16 LE][expected_revision:u32 LE]`。
首页 start_index=0、expected_revision=0；续页携带首页返回的修订号。
max_bytes 限制记录区，不含应答头，当前主机使用 3500。

成功应答（位于通用 status 后）：
`[revision:u32 LE][next_index:u16 LE][records…]`。
单条记录为 `[address:3B][core:6B][name_length:u8][ASCII name][ext_length:u16 LE][ext_TLV…]`。
核心 6 字节与 ATTR_CORE_READ 完全相同：[type][access][flags][state][elem_count:u16 LE]；名称为 1..255B 可打印 ASCII、不含 NUL；扩展 TLV 与 ATTR_EXT_READ 完全相同，ext_length 可为 0。单条完整记录须能放进 3500B 记录区，生成器对此检查。
顺序按固件参数目录索引；每条完整记录仅属于一页，next_index=0xFFFF 表示结束。
请求空间放不下下一条完整记录且本页尚无记录时返回 LENGTH；不允许空页、不前进游标或截断记录。

固件对一条记录只读取一次有效属性，编码核心和扩展字段；页面生成前后修订号不同、
或续页期望修订号与当前不同时，仅返回 STATE(0x0A)。
上位机丢弃本轮所有暂存记录，最多从首页重试一次；再次变化则终止同步。
完整地址集、名称、类型、元素数、TLV 和游标全部验证成功，且与树参数地址一一对应后才能发布目录。
现有 0x04/0x10 保留用于少量动态属性变化。v4 主机要求配套 v4 固件，不退回逐项加载。

C/C# 共用向量（包含 status，单项 TEXT8 ProductCode、ROO、可见、修订号 1）：
`00 01 00 00 00 FF FF 01 01 03 0A 02 01 01 01 00 0B 50 72 6F 64 75 63 74 43 6F 64 65 00 00`。

### 7.6 VALUE_READ（0x05）

请求：`[0..2]=参数地址 [3]=元素索引（标量填 0）`。
应答：`[0]=status [1..2]=value_len [3..]=值（按类型编码）`。COMPOSITE 原样返回。

### 7.7 VALUE_WRITE（0x06）

请求：`[0..2]=参数地址 [3]=元素索引 [4..5]=value_len [6..]=值`。
应答：`[0]=status`（成功仅 1 字节）。

可读可写参数收到成功应答后，主机必须独立发起 VALUE_READ 比对，才确认本次 RAM 写入；失败写入绝不自动重发。RWA 写入置 pending，RWO 只改 RAM。OWO 仍执行权限、索引、长度和范围校验，但 fake 固件校验通过直接回成功，不改变命令槽、不触发电机/学习/保存/复位。OWO 不可读，不能伪造独立读回成功。

### 7.8 VALUE_READ_BATCH（0x07）—— 实时轮询通道

请求：`[0]=count（1..64）`，随后 count × `[3B 地址][1B 元素索引]`。
应答：`[0]=status`（帧级：0=已处理），随后 count 项，每项 `[1B item_status][2B len][值]`；单项失败不影响其他项（item_status 非 0 时 len=0）。

轮询建议批量 ≤32 项以控制单事务时延。

### 7.9 STATE_READ（0x08）

请求：`[0..2]=参数地址 [3]=保留`。
应答：`[0]=status [1]=state`（bit0=运行时可见，bit1=值已修改未持久化，其余保留）。

### 7.9.1 ATTR_CORE_READ（0x10）

请求：[0..2]=参数地址，[3]=保留且填 0。

应答：[0]=status，[1]=类型，[2]=当前有效权限，[3]=核心标志，[4]=运行时 state，
[5..6]=元素数 u16 LE。核心标志 bit0 仍表示初始默认显示；state bit0 表示运行时可见，
bit1 表示待持久化。默认隐藏与运行时不可见是两个独立维度。

权限、默认显示和运行时状态可以原位刷新。类型或元素数改变属于结构变化，主机停止业务操作并重连，
重新执行完整目录加载。地址不存在回 0x01。

### 7.9.2 CHANGE_QUERY（0x11）

请求固定 12 字节：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0..3 | since_revision | 主机已应用的修订号 u32 LE |
| 4..7 | snapshot_revision | 首包填 0；续页必须回填首包返回值 |
| 8..9 | cursor | 首包填 0；续页填上一应答的 next_cursor |
| 10..11 | max_bytes | 本页变化条目最大字节数，不含应答头 |

应答：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | status | 状态码 |
| 1..4 | snapshot_revision | 本轮固定版本边界 |
| 5..8 | current_revision | 应答时设备最新修订号，可大于快照 |
| 9..10 | next_cursor | 下一日志游标；0xFFFF 表示本轮完成 |
| 11 | flags | bit0=必须全量重同步 |
| 12.. | entries | 重复 [3B 地址][1B change_mask] |

change_mask：bit0=state，bit1=核心属性，bit2=扩展属性。主机合并同地址的掩码；分页期间只返回
(since_revision, snapshot_revision] 内的变化。新的变化留给下一轮，防止翻页过程中边界漂移。

日志覆盖、快照晚于当前修订、since 晚于快照或设备复位导致修订失效时置 flags.bit0，并以
next_cursor=0xFFFF 结束。主机通过 ATTR_SNAPSHOT_PULL 重新读取所有已知参数的核心与扩展属性；若地址、类型、元素数或树结构
不再匹配，则重连并重新加载 TREE_PULL/ATTR_SNAPSHOT_PULL。正常通信建议每秒查询一次，先刷新当前页面，
其余只更新缓存或标记失效。普通值变化仍由 VALUE_READ_BATCH 采样，不写入此日志。

### 7.10 ERRTEXT_PULL（0x09）

游标分块（§7.2）。条目：`[1B 错误码][1B 文本长][ASCII 文本]`。

### 7.11 MSC 内容更新（0x0A~0x0D）

四条命令均为写事务，超时、CRC 错误或应答丢失时不得自动重发。停等单事务；
擦写及校验在主循环中分步执行，完成后用原 SVC/TID 应答。器件故障回 0xFF，
校验不符回 0x07。纯内容模块为 `src/content/bvpv_cd_store.*`。

**MSC_UPDATE_BEGIN（0x0A）**

请求固定 8 字节：`[0..3]=总字节数u32 LE [4..7]=整盘CRC32 u32 LE`。
应答：`[0]=status [1..2]=块尺寸2048`。

固件独立要求镜像非零、2048B 对齐且不超过单槽容量 4,194,304 字节。没有镜像版本、同版本标志或防降级判断。
已有会话回 0x06，Flash 硬件故障回 0x0A；无有效盘仍可开始更新。所有前置检查在擦写之前完成。
上位机在同一只读文件句柄上检查长度后才读取镜像；发送 BEGIN 前查询 MSC_INFO 并与设备报告的单槽容量再次比较。
拒绝时显示实际大小与上限，不发送 BEGIN/BLOCK/FINISH/ABORT，不擦写，并释放已取得的更新作用域。
BEGIN 预留 SPI2，向备用元数据扇区提交更高序号的无介质记录并回读核实后才应答。
随后收到各 4KB 扇区首块时擦除唯一光盘槽；BEGIN 无介质提交不触发成功重枚举。
会话预留只阻止电机获取总线，Flash 各条指令仍独立获取/释放事务锁。

**MSC_UPDATE_BLOCK（0x0B）**

请求：`[0..3]=镜像内偏移 [4..5]=data_len(2048) [6..2053]=数据`。
应答：`[0]=status [1..4]=期望的下一偏移`。

偏移严格连续且不越界；重复、回退和跳跃回 0x0B，不推进状态。
逐页编程完成后独立回读整个块并逐字节比对，再应答成功。帧 CRC16 保护传输，
回读检查器件实际写入。本版本不支持断点续传或块重发。

**MSC_UPDATE_FINISH（0x0C）**

请求无载荷。应答：`[0]=status [1]=action(0x01，即将重枚举)`。

要求已收完整镜像。分段回读整盘并核对 BEGIN 的 CRC32，随后写入提交记录；
提交标志独立编程、最后写入。**有效镜像提交标志是生效点**：BEGIN 已使旧盘失效，FINISH 提交前失败保持空盘；之后即使 FINISH
应答丢失也可能已生效。主机通过 MSC_INFO 按同 UID 重连、空闲状态、长度、CRC 和递增提交序号核实结果，不能重发。

最后一张 HID 报表经 TinyUSB 完成回调确认后，等待 100ms，内部上拉软断开 250ms 后重连。
500ms 发送看门狗到期亦重枚举，供主机查询。新介质在重新挂载后才可读；PE4 始终高阻。

**MSC_UPDATE_ABORT（0x0D）**

请求无载荷，应答 `[0]=status`。退出未完成会话；BEGIN 无介质记录已提交时保持空盘，不能恢复被覆盖的旧镜像；空闲时幂等成功。
必须遵守单事务规则，不能与未完成的 BLOCK/FINISH 并发。
断线、总线复位或会话空闲 30 秒也触发取消；已启动的 Flash 指令先结束，下一操作不再启动。
已经发出的提交标志不能撤回。器件超时/通信故障时保持无介质并提供 HID 查询，复位后重新校验恢复。

更新期间 MSC 报无介质并提供介质变化事件，HID 保持枚举。
结束/中止释放 SPI2 会话预留；Flash 忙碌期间不能普通读取其他分区。

### 7.11.1 MSC_INFO（0x0F）

请求无载荷，只读，可按 §4.1 重试。成功应答固定 25 字节，多字节字段小端：

| 应答偏移 | 字段 |
|---|---|
| 0 | status |
| 1 | 存储布局版本，4；Andromeda 兼容旧设备布局3 |
| 2 | 更新状态：0空闲、1接收、2擦写、3校验、4提交、5取消等待、6器件故障 |
| 3 | flags：bit0有经校验的有效镜像，其余位为 0 |
| 4 | 最近错误码，成功 BEGIN 清零 |
| 5..8 | 单槽容量，4194304 |
| 9..12 | 活动镜像字节数 |
| 13..16 | 活动镜像 CRC32 |
| 17..20 | 最新已提交记录序号 u32，无介质记录也计入 |
| 21..24 | 本次会话下一偏移，结束后保留，下一次 BEGIN 清零 |

bit0 表示存在经校验的活动镜像，不保证介质此刻可读；更新期间可暂报无介质。
无有效镜像时长度和镜像CRC均为零，提交序号仍报告最新记录；没有有效新记录则序号为零。
状态6为器件故障；状态0且bit0=0仍允许整包重刷。旧布局识别通过last_error=0x09提示，损坏记录/镜像通过0x07提示；启动均不擦写。
未支持 MSC_INFO 的旧固件回0x09，新工具据此停止。
提交序号按 u32 模运算比较，差值位于 (0,0x80000000) 表示较新。

### 7.12 ECHO（0x7F）

请求：N 字节（成功回显上限 4087，以给应答 status 留 1B）。应答：`[0]=status` + 原样 N 字节；4088B 请求返回长度错误。用于链路诊断与产测。

### 7.13 签名 MCU 固件升级（0x0E、0x13、0x20–0x23）

首版固定 STM32F446VET6 / `BV500-F446`。Boot 仅 HID，PID 为 `USB_PID_BOOT`；APP 保留 HID+MSC / `USB_PID_APP`。两者 USB 序列号使用相同完整芯片 UID。Boot 通过 FW_INFO 握手，不拉参数目录。MCU 能力位使用 `0x0004`：`0x0002` 已由 Andromeda 用于参数持久化，不得重用。

固定内部 Flash：Boot 扇区 0–3，`0x08000000–0x0800FFFF`（64KiB）；512B 元数据 `0x08010000–0x080101FF`；应用与向量表 `0x08010200–0x0807FFFF`，实际容量 458,240B。升级只擦除扇区 4–7，不写 Boot、公钥、EEPROM、校准或外部 W25Q64。

#### 7.13.1 .afw 发布包

文件必须恰好 `256B 签名头 + 实际应用二进制`。不接受 ZIP、CPA 旧封装、尾部数据；`.aky` 保持光盘含义。ASCII 字段必须非空、NUL 终止并补零（版本 1–31B 可打印 ASCII）。

| 签名头偏移 | 编码 |
|---|---|
| 0–3 | ASCII `AFW1` |
| 4–5 / 6–7 | `header_size:u16=256` / `format:u16=1` |
| 8–23 | `target:16B=BV500-F446` |
| 24–27 / 28–31 | `app_base:u32=0x08010200` / `image_length:u32`，8–458240 |
| 32–63 | `firmware_version:32B` |
| 64–95 | 实际应用长度上的 SHA-256（不含 Flash 填充） |
| 96–97 / 98–191 | `boot_contract:u16=1` / 94B 全零 |
| 192–223 / 224–255 | P-256 ECDSA `r / s`，各 32B 大端 |

签名对象为头部 `[0..191]` 的 SHA-256。公钥固定编译进 MCU 和 Andromeda，64B 大端 `X||Y`；包不能携带替代公钥。设备使用 Mbed TLS 3.6.6 验签，主机使用 SHA256/ECDsaCng 预检。全零未配置公钥拒绝所有包。允许合法旧版本和重复刷写；无防回退计数。

Flash 元数据区域 `[0..255]` 在 FINISH 时写入签名头；`[256..507]` 保持 `0xFF`；`[508..511]` 为 LE 提交字 `0xA55AC33C`（地址 `0x080101FC`），最后单独编程并回读。512B 不全部存签名，也不出现在 `.afw` 文件中。

#### 7.13.2 FW_INFO

空请求；成功载荷严格 149B（含 status），失败仅 status：

| 载荷偏移 | 字段 |
|---|---|
| 0 | status:u8 |
| 1 / 2 / 3 / 4 | mode / state / flags / last_error，各 u8 |
| 5–16 | uid:12B，三个 MCU UID word 按 LE；格式化为三个 8 位十六进制字即 USB 序列号 |
| 17–32 | target:16B |
| 33–34 / 35–36 | boot_contract:u16 / max_block:u16=1024 |
| 37–40 / 41–44 / 45–48 | app_base:u32 / capacity:u32 / next_offset:u32 |
| 49–80 / 81–112 | active_manifest_hash / session_manifest_hash，各 32B |
| 113–144 / 145–148 | firmware_version:32B / active_image_length:u32 |

`mode` APP=1、BOOT=2；`flags.bit0` 表示经过提交字、签名、全文摘要和向量验证的有效应用。`state`：Idle=0、AwaitErase=1、Erasing=2、Receiving=3、Verifying=4、Committed=5、Failed=6。APP 报 Idle、会话/偏移为零。manifest hash 是签名头前 192B 的 SHA-256；无有效应用的活动字段、无会话的会话字段填零。

#### 7.13.3 命令与提交时序

ENTER_BOOTLOADER 空请求：APP 检查维护条件，不允许动作、学习、保存或光盘更新中进入 Boot；缺少真实维护检查时返回 Busy。Fake 明确无业务动作，其检查返回空闲。成功应答只有 status。实际 IN 完成后写 SRAM 顶部 8B `.boot_request` 的互补字，软件复位；Boot 清除并消费。冷启动/掉电复位不接受残留标记。

FW_BEGIN 请求必须 256B 头。格式、目标、地址、容量、契约与签名通过前零擦写；通过后进入 AwaitErase，成功应答只有 status。最后 IN 报表实际完成后才授权动作：软断开 USB，依次擦除扇区 4、5、6、7 各一次，再以相同 Boot PID/UID 重新枚举。未完成发送、断线或 TX watchdog 撤销 AwaitErase。主机最长等待 30s，以同 UID、同 session_manifest_hash、Receiving、next_offset=0 为传输依据。Receiving/Failed 可由显式新 BEGIN 整包重新开始。

FW_BLOCK 请求 `[offset:u32][data:1–1024B]`。块固定 1024B，仅最终块允许不足；offset 必须等于 next_offset。每次编程后完整回读；成功载荷 `[status=0][next_offset:u32]` 共 5B。末尾不足 word 补 `0xFF`，摘要仍只覆盖实际长度。失败不会凭收到报文推进偏移。

FW_FINISH 空请求：仅全部实际长度接收后有效。回读完整应用并验证 SHA-256；SP 必须 8B 对齐且在 `0x20000000 < SP <= 0x2001FFF8`，Reset 必须 Thumb 且落在实际应用范围。随后写入并回读签名头，最后提交字。成功应答只有 status，实际 IN 完成后复位。若应答未完成，保留可查询的 Committed/有效应用证据，不强行宣布主机成功。

RUN_APP 空请求：仅经过完整验证的应用允许返回，成功应答只有 status，实际 IN 完成后复位；无有效应用回 State。每次上电/软件复位都验证提交字、头签名、完整应用摘要和向量表；失败留在 Boot。有效应用直接启动，无 USB 救援等待窗口。

#### 7.13.4 主机恢复与成功依据

单事务、FLAGS/TID/CRC/分片沿用 v4。FW_INFO 200ms 可重试一次；BEGIN/BLOCK/ENTER/RUN 2s，FINISH 15s；写事务不自动重发。BLOCK 丢应答仅查询 FW_INFO；同会话、Receiving、next_offset 已推进至本块末尾才继续。FINISH 丢应答仅查询有效活动 manifest、版本、长度及 UID；证据不足进入“结果待确认”，不再发更新写命令。掉电或 MCU 复位丢弃未完成 RAM 会话，必须 BEGIN 整包重刷。

Andromeda 沿用“工具 → 更新”窗口，单个 `.aky` 或 `.afw`。绑定原 UID，PID/路径变化不切换其他设备；重复 UID 拒绝自动选择。纯 Boot 启动进入恢复更新窗口。BEGIN 前可通过停止操作取消，并通过 RUN_APP 返回原有效应用；同步进入发送 BEGIN 阶段后禁用取消。更新开始后拒绝更新窗口及其所有者的正常关闭请求，验证、提交、新工作区确认及摘要期间持续保护；关闭请求不停止传输、不弹阻塞提示。现场须先停机隔离。

传输期间主机进程崩溃或被强制结束，本次升级视为失败；擦除后尚未提交的应用无效，设备留在 Boot，重新启动 Andromeda 从 BEGIN 整包恢复。原生 USB 更新占用随进程退出自动释放，遗留文件锁不能隐藏恢复设备。中断轮次不能沿用旧工作区或报告成功；仍按设备提交证据及新工作区 Ready 判断后续恢复结果。关闭与进程退出实测见 [验收记录](https://github.com/f1rstzi0n/USB-HID/blob/usb-hid-archive-20261012/docs/validation/ANDROMEDA-MCU-CLOSE-20261010.md)。

完成必须确认同 UID、有效目标 manifest、版本和长度，并完整拉新目录使新工作区 Ready；升级 scope 不恢复旧目录。普通断线恢复仍保留原结构校验。合法但启动卡死的应用、Boot 或公钥维护使用 SWD。新固件发布前验证 EEPROM/校准持久数据兼容性；升级不迁移或回写参数。板级时序、链接、发布与验收见 [Boot 设计](BOOTLOADER_DESIGN.md)、[官方依据](https://github.com/f1rstzi0n/USB-HID/blob/usb-hid-archive-20261012/docs/BOOTLOADER_RESEARCH.md)。


### 7.14 外部参数目录（0x30–0x36）

HELLO capabilities bit3 `0x0008` 表示支持外部目录；帧、三字节地址、旧服务载荷保持 v4。没有此能力的现有 v4 设备继续完整 TREE_PULL + ATTR_SNAPSHOT_PULL 加载。

#### 7.14.1 CATALOG_INFO（0x30）

空请求返回 `[status1][data133][app_identity ASCII]`。下表偏移以 **status之后的data** 为起点，app身份长度0..63。

| data偏移 | 字段 |
|---|---|
| 0 | 格式1 |
| 1 | 状态：0空闲、1预检中、2预检通过、3写入中、4启动验证/回读验证、5硬件故障 |
| 2 | 目录有效标志0/1 |
| 3 | 最近错误码 |
| 4..7 | 参数区容量，u32 |
| 8..11 | 活动包总长度，u32；无有效目录为0 |
| 12..15 | 最新管理记录序号，u32 |
| 16..17 / 18..19 / 20..21 | 参数数 / 树记录数 / 主窗口绑定数，u16 |
| 22..23 | 保留0 |
| 24..27 | 运行属性修订，u32 |
| 28..31 | 会话token，u32；无会话为0 |
| 32..35 | 下一正文偏移，u32 |
| 36..67 | 活动正文SHA-256；无有效目录全0 |
| 68..99 | 固件运行结构契约SHA-256 |
| 100..131 | 目录schema SHA-256 |
| 132 | app身份ASCII长度 |
| 133.. | 不含NUL的app身份 |

范围请求恰好6B：`[package_offset u32][bytes u16]`，bytes为1..3500，含头在内不越过活动包总长度。返回 `[status][bodySHA32][package_offset4][raw bytes]`。只读获取目录，主机核实每页摘要、偏移并自行验证整个签名包。启动验证尚未结束（状态4且token0）时，只读等候并支持取消；空闲且无有效目录提供恢复入口。

#### 7.14.2 完整动态快照（0x31）

请求与0x12一样为8B：`[cursor u16][max_bytes u16][expected_revision u32]`。expected_revision0建立快照，其余分页必须匹配同一非零修订。响应 `[status][revision4][next_cursor2][records]`，next=FFFF结束。每个运行契约地址恰好一条：

`[address3][access1][state1][min_len1][max_len1][min][max]`

min/max长度为0或该数值类型的元素字节数（≤8）。静态名称、树、类型、元素数量、默认显隐、枚举与单位由签名包给出。USB有效权限和范围为运行约束、动态状态与已挂载目录限制的交集；pending来自设备RAM，目录不能清除pending。修订变化、重复/遗漏地址或零进展页必须拒绝并重新完整同步。

#### 7.14.3 主窗口绑定（0x32）

4B请求 `[cursor u16][max_bytes u16]`，响应 `[status][next_cursor u16][records]`；每条为 `[role_len1][role ASCII][address3][order1]`，无长度前缀。其内容与包UI段相同。首版只支持现有29种role及对应业务地址，目录可选成员和调整顺序；不引入任意页面、脚本或动作编码。学习等按钮沿用既有完整工作流。

#### 7.14.4 两遍目录事务

- BEGIN（0x33）请求520B：`[mode1][reserved3=0][session u32][header512]`。mode0为完整预检、session0；验证头及专用域签名后返回 `[status][session4]`。维护预留成功后才建立会话，预检全程零擦写。
- BLOCK（0x34）请求 `[session4][body_offset4][data1..3500]`，只接受严格连续正文偏移；应答 `[status][next_body_offset4]`。预检流式验证结构、全集、类型、元素数、约束、索引和摘要。相同文件第二遍才落盘。
- FINISH（0x35）请求session4，应答仅status。mode0完成正文SHA及结构校验，进入状态2；失败释放会话并保留原有效目录。
- 第二遍BEGIN使用mode1、同一session和逐字节相同签名头。先提交并回读“无效目录”管理记录，再擦写包头，才应答BEGIN；随后按4KiB扇区随写随擦，按256B页写。FINISH重新读取完整包、验签、摘要及运行约束，通过后最后提交有效记录。
- ABORT（0x36）请求session4，应答仅status。断线/总线复位/空闲30秒同样取消；已发出的Flash操作先结束，已开始的提交标志必须核实。覆盖期间取消可能留下无有效目录。
- 写事务不自动重发。丢应答仅用INFO核对状态/token/进度/活动摘要及序号；不能确定结果时报告待确认，整包重刷恢复。有效提交应答实际IN完成后软断开重枚举；该应答看门狗超时不触发重枚举，主机可INFO确认后主动重建工作区。预检FINISH不重枚举。

BEGIN/BLOCK/ABORT超时2000ms，FINISH15000ms；读取仍200ms。上位机在覆盖FINISH之后释放旧独占句柄，等待700ms软断开/重枚举，在20秒总确认时限内仅向同UID读取INFO，确认目标正文摘要及应用身份；正常应答和丢应答均不重放写请求。目录和光盘会话不能并发，维护期暂停普通参数操作及业务动作，诊断查询保留。目录缺失/损坏不改变设备业务运行规则。

#### 7.14.5 ACAT v1发布包与缓存

包最大1MiB，固定512B头，签名前448B，末64B为大端原始P-256 r/s。摘要为 `SHA256(ASCII "BVPV-CATALOG-V1" + NUL + header[0..447])`，与AFW签名域独立；复用既有发布公钥和密码实现。

| 头偏移 | 字段 |
|---|---|
| 0..3 / 4..5 / 6..7 | ASCII ACAT / 格式u16=1 / 头长u16=512 |
| 8..11 / 12..15 | 总长度 / 正文长度，u32 |
| 16..31 | 目标ASCII BV500-F446，NUL补齐 |
| 32..63 / 64..95 / 96..127 | runtime / body / schema SHA-256 |
| 128..159 | 非空版本ASCII，NUL终止并补齐 |
| 160..167 | PARAM、TREE、UI、ERR计数，各u16 |
| 168..207 | PARAM/TREE/UI/INDEX/ERR五段，各为正文offset u32+length u32 |
| 208..447 | 保留0 |
| 448..511 | 签名r32+s32 |

五段连续、无重叠、覆盖整个正文。PARAM为0x12原始记录但state0；TREE为0x02原始记录；UI为0x32原始记录；ERR为 `[code1][text_len1][ASCII]`。这四段每条前加u16LE长度；INDEX为每条PARAM、TREE的u32LE正文偏移，指向记录wire首字节，其前2B提供记录长度。schema字符串为 `BVPV-CATALOG/1;PARAM=v4;TREE=v4;UI=role-address-order;INDEX=offset32;ERR=code-text;LE`，SHA-256为 `ef9633bd43ee9995a4650574f88f6ac49a1f03c9b7f70cc67cb7432e470affbf`。

runtime摘要规范为 `ASCII "BVPV-RUNTIME-1"`（14B，不含NUL）+参数数u16LE+按地址排序的8B记录 `[address3][type1][elem_count2][elem_size2]`。Undefined的size0；COMPOSITE使用实际尺寸。设备还逐条校验实际权限、硬范围与USB限制，不能只信任摘要。默认值TLV是描述数据，不赋值RAM；既有默认值可在当前写范围之外，实际写入仍严格检查范围与finite。

设备最多2300参数、64个不同于硬范围的稀疏范围限制，单记录最多3500B；超过这些上限在预检中零擦写拒绝。参数名称、group key和role唯一，错误code唯一，树每地址唯一且完整；名称/分组ASCII、枚举/单位UTF-8均严格验证。固件不保留完整字符串或全量目录副本。

冷连接验证HELLO→INFO→签名静态包完整树/属性/UI/ERR→同一修订全动态快照→必要初值，完成后Ready。USB发现和HELLO核对VID/PID及设备类型；缓存键由UID、固件目标、app身份、活动manifest以及schema/runtime/body摘要生成。缓存文件重新验签，并检查格式和活动身份，命中仍重新获取全动态快照与初值。每次连接重新绑定UID。更新后的新工作区必须确认原UID、目标目录摘要和完整Ready，保留设备RAM值/pending并丢弃旧界面未提交草稿。

## 8. MSC 接口与 W25Q64 布局

MSC 为 Interface 1、08/06/50、BOT、单 LUN、只读 CD-ROM，扇区2048B。
.aky 是原始 ISO9660 镜像，无额外封装；固件不解析文件系统，主机预检长度、对齐及主卷描述符。

| 区域 | 地址（含末地址） | 容量 |
|---|---|---|
| 上位机光盘，单槽 | 0x000000–0x3FFFFF | 4MiB，4194304B，2048扇区 |
| 签名参数目录，单槽 | 0x400000–0x4FFFFF | 1MiB |
| MCU程序预留 | 0x500000–0x7EFFFF | 3008KiB |
| 管理元数据 | 0x7F0000–0x7FFFFF | 64KiB |

MCU预算共3MiB，包含末尾64KiB管理元数据。分区常量集中在src/content/bvpv_cd_meta.h。
参数目录使用§7.14；MCU外部区继续预留，RAM初始化和内部Flash升级保持原行为。
光盘擦写仅触及光盘区及两个记录扇区，不执行整片擦除，不改预留区。

光盘两个提交记录位于0x7F0000和0x7F1000，各独占4KiB擦除扇区；目录记录在0x7F2000/0x7F3000（见§8.2），其余48KiB保留。
记录32B，交替提交；两记录管理同一镜像，不代表两份内容副本。

| 偏移 | 字段 |
|---|---|
| 0..3 | magic ASCII BVC4 |
| 4 | 格式版本4 |
| 5 | 类型：0有效镜像、1无介质记录 |
| 6..7 | 保留，必须为0 |
| 8..11 | 镜像字节数u32 LE；有效镜像非零、2048对齐、不超过4MiB；无介质为0 |
| 12..15 | 镜像CRC32 u32 LE；无介质为0 |
| 16..19 | 提交序号u32 LE，按模2^32递增 |
| 20..23 | 成功镜像写入计数u32 LE；无介质记录保留此前计数 |
| 24..27 | [0..23]的CRC32，u32 LE |
| 28 | 最后独立编程的提交标志：0xA5有效，0xFF未提交 |
| 29..31 | 保留，必须为0xFF |

每次元数据提交：擦除备用记录扇区，写[0..27]并回读全32B，确认提交/保留字节仍为0xFF；
最后独立编程[28]=0xA5，并回读验证完整记录。另一份已提交记录保留。
BEGIN先提交序号S+1的无介质记录并核实，再应答允许光盘覆盖；FINISH整盘CRC通过后提交S+2的有效镜像记录。
无介质记录不是更新成功，不触发成功重枚举。只有有效镜像提交才触发原有HID发送完成后的重枚举。

启动只读验证最新已提交记录；HID尽早枚举，目录验证优先、光盘CRC随后分步读取，每轮后台读取≤256B并让出主循环。光盘完整CRC通过才提供介质；无介质记录或CRC不匹配保持空光驱。
相同序号但内容冲突、或两序号相差0x80000000导致先后不明时，报告CRC错误并保持空光驱；完全相同的重复记录可挂载。
单槽内容已可能被覆盖，禁止回退旧记录。空白、坏记录、旧布局均不自动初始化或恢复工厂盘。
Flash硬件故障保持HID与空光驱，拒绝写入；非硬件故障的空盘可通过显式BEGIN整包重刷。

CRC32沿用IEEE 802.3/zlib：反射多项式0xEDB88320、初值0xFFFFFFFF、末取反。
镜像CRC覆盖全部镜像字节，不含管理元数据；头CRC覆盖[0..23]。
LBA地址为光盘起址 + LBA×2048 + 块内偏移，读取以实际有效镜像长度为界。

### 8.1 旧布局与恢复

BVC3/BVC2/BVCD仅识别并提示，不自动迁移、不自动擦除。旧盘需在升级前保留原.aky或读回完整镜像并校验。
用户明确执行重灌后才经现有.aky入口写入新布局。上位机兼容布局3和4，并以设备报告容量为准。
新固件不挂载旧分区；回刷旧固件前同样需要备份与明确重灌，不能把新记录按旧地址解释。

取消、断线、超时或断电后不自动重发写请求；读取同UID、布局、状态、有效镜像标志、目标长度/CRC及序号复核。
仅序号前进不能证明成功，因为无介质记录也前进序号。确认空盘后提示重新刷入完整镜像，参数工作区仍可恢复。

软件验证与实板边界见 [2026-10-10 分区验收记录](https://github.com/f1rstzi0n/USB-HID/blob/usb-hid-archive-20261012/docs/validation/FLASH-PARTITION-V4-20261010.md)。

### 8.2 参数目录提交记录

目录两个记录位于0x7F2000/0x7F3000，各独占4KiB擦除扇区，独立于BVC4。记录96B：

| 偏移 | 字段 |
|---|---|
| 0..3 / 4 | ASCII ACC1 / kind：0有效、1无效目录 |
| 5..7 | 保留0 |
| 8..11 | 序号u32，模2^32递增 |
| 12..15 | 包总长度u32；无效目录为0 |
| 16..47 | 正文SHA-256；无效目录全0 |
| 48..79 | 当前运行结构契约SHA-256，两种kind均存 |
| 80..83 | 前80B的IEEE CRC32，u32 |
| 84..91 | 保留FF |
| 92 | 最后单独编程的提交标志A5；未提交FF |
| 93..95 | 保留FF |

交替擦除记录扇区，写前92B并完整回读，最后独立写提交标志并再回读。先持久化无效目录才允许覆盖单槽；最终有效记录绑定实际读回的目录和运行契约。最新无效记录、冲突/先后不明记录或最新有效包损坏均不回退旧目录，不做启动擦写。其他管理区仍保留。

## 10. 版本与演进规则

1. FLAGS 低三位与 HELLO 版本统一为 4，正常请求/应答 FLAGS 为 0x04/0x84。固件、Andromeda 和 hid_smoke 同步升级；不支持旧版回退或旧树格式协商。
2. 保留位/字节由发送方填 0。帧 FLAGS、树记录种类/地址/父关系及字段边界严格校验；扩展 TLV 的未知 tag 可按长度跳过，不能用 capability 位改变树布局。
3. v4 范围内新增服务须分配新 SVC，既有报文布局保持稳定；废弃服务回 0x09。再次改变布局须升级主版本并同步两端。
4. 连接根据外部目录能力使用§7.14的签名静态缓存+完整动态同步；无此能力继续HELLO→完整TREE_PULL→ATTR_SNAPSHOT_PULL。Ready始终要求完整校验完成。
5. 正常通信每秒 CHANGE_QUERY；溢出、修订失效或重连全量同步。默认隐藏独立于运行时不可见；Ctrl+Shift+H 只能显示默认隐藏项，不能绕过权限或运行时限制。类型/元素数/地址/树结构变化通过重连加载。
6. USB 描述符序列号为三个完整 MCU UID 字构成的 24 位十六进制串，和业务序列号分别存储。断线停止业务、缓存失效；只恢复相同明确 UID，重复身份必须人工选择，不重放失败写入、学习、保存或重启命令。

### 10.1 本分支 fake 行为与验收边界

Debug/Release 均使用版本 `SW110048.1.4.9`；USB 身份为 `1209:0001` / AURASKY / BV500-USB。参数和默认值从仓库冻结来源可重复生成。普通写入仅存 RAM，保持外部供电的 USB 拔插保留；MCU 复位或断电恢复编译初值。

不模拟电机、压力、自学习、EEPROM 保存和软件重启，无业务变化模拟器。OWO 仅校验并成功应答。RWA pending 与属性变化记录保留；RAM 读回不能作为业务动作或持久化成功证据。MSC 使用真实 W25Q64 内容后端。v4/BVC4与外部目录本轮已在F446实板安装，完整目录连接、目录恢复及真实SCSI读盘通过，见[2026-10-10实板验收](https://github.com/f1rstzi0n/USB-HID/blob/usb-hid-archive-20261012/docs/validation/USB-CATALOG-HARDWARE-20261010.md)；真实擦写瞬间断电和电源边沿计时仍待单独验收。

C/C# 共用帧向量：`7F 03 34 12 03 00 10 20 30 03 77`（ECHO，请求 TID=0x1234，载荷 10 20 30，CRC=0x7703）。

## 附录 A：与 BVPV（RS485）的对应关系

| 维度 | BVPV / RS485 | BVPV-USB |
|---|---|---|
| 参数寻址 | 3 字节 类/实例/属性 | 同；具体服务另跟索引或保留字节 |
| 读 / 写服务 | `0x80` / `0x81` | VALUE_READ `0x05` / VALUE_WRITE `0x06` |
| 应答模型 | 读=完整帧；写=单字节 ACK `0x06`/NAK `0x16` | 统一应答帧 + 载荷首字节状态/错误码 |
| 值编码 | 二进制小端 | 原样继承 |
| 成帧 | 站地址 + STX + 长度 + Pad + sum8 | HID 报表 + 分片层 + SVC/FLAGS/TID/LEN + CRC16 |
| 事务恢复 | 读可重试一次，写不重发 | 原样继承 |
| 写后读回验证 | 独立读回比对 | 原样继承 |
| EEPROM 持久语义 | RWA 进 pending 集，显式保存 | 保留 pending，fake 分支不实现保存 |
| 广播 | 仅 MACAddress 单发发现 | 不适用（USB 点对点） |
| 参数目录 | 上位机携带 .dat 文件 | **设备自描述**（TREE_PULL/ATTR_SNAPSHOT_PULL/ATTR_EXT_READ） |

**不继承**：站地址字节、STX/Pad/sum8、单字节 ACK/NAK、波特率与字符间隔概念。
**原样继承**：三字节寻址、类型编码、权限矩阵、写后读回、写不重发、EEPROM 持久语义、COMPOSITE 语义（含 `AndromedaCMD 0x6801FE` 四 Float32 布局，实时轮询由 VALUE_READ_BATCH 承载时保持字段序）。
